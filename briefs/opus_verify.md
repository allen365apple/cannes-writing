# 派工時把 {Y} 換成年份、{BATCHES} 換成 3～4 個批號（例 b005 b006 b007 b008）。模型：Opus 5.5。所有路徑都相對於本專案根目錄。
# 派工前主對話先跑：python3 tools/check_batches.py {Y} {BATCHES}，並確認這幾批的寫手都已停手。

你是坎城 {Y} 的審稿人。{BATCHES} 是 Sonnet 寫好的批次，請驗證，發現問題直接修好。全程繁體中文。

## 先讀
1. 規則卡：rules/writer_rules_card.md
2. 程式檢查報告：years/y{Y}/checks/check_{BATCHES 用底線相連}.md（格式、字數、標籤、圖片能否開、壞網址、有 case board 沒用、疑似成效句、【得獎】行與官方預填不同，程式都掃過了）

## 檔案（O=years/y{Y}）
- 稿：O/<批號>_out.json；輸入（含官方預填 `official`、`image_candidates`）：O/<批號>_in.json
- **改任何一批之前，先複製原檔到 O/tmp_verify_<批號>/before_<批號>_out.json**

## 要做的
1. **處理報告裡每個被標的件**：能修就修（換 case board、修壞網址、刪成效句、【得獎】行改回官方 award_line——除非寫手有充分理由）；「疑似成效」要人判斷，背景數字保留。
2. **每件讀一遍一句話**：當沒背景的台灣同事讀。做法講清楚、有主詞、沒聽過的品牌有身分、逗號沒拆錯、沒有抽象比喻、沒寫成效或得獎。不好的直接改，舊句存 idea_one_liner_r0（已有就存 r1）。
3. **讀稿掃一遍**：有沒有從圖推測、寫成事實的內容；有沒有寫錯支（對 `official.awards[].entry_titles`）。
4. **事實抽查：每批至少 2 件**，打開 references 核對人名、數字、做法。對不上就改；改不了標 uncertain 並在 note 寫缺什麼。
5. **圖：每批至少下載 3 張用 Read 打開看**，確認是這件、看得出點子。
6. **uncertain 的件**：自己再找來源補強，補得起來就改寫並拿掉 uncertain。
7. 疑似重複（同一個點子的不同版本、清單同一件列兩筆）：判斷並寫理由，**不要自己改 decision**，回報給主對話。

## 鐵則
- 絕對不能用 rm 或任何刪檔指令；只改 {BATCHES}；不寫 Google、不上傳、不 git（git 由主對話統一做）。
- 改過的件在 note 最後加「<日期> Opus 驗：…」。每批改完寫回、讀回確認 JSON 有效、筆數與 id 順序不變。

## 回報（300 字內）
每批：通過幾件、改了哪些（一句話／成效／圖／事實）、事實抽查結果、仍 uncertain 的件與缺什麼、待決事項（重複候選、【爭議】候選）。
