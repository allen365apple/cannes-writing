# 坎城案例寫手規則卡（精簡版，2026-10-31）
> 正本是 `得獎案例寫進靈感倉庫的方法.md` 第二～五節與 `點子撰寫規則.md`；兩者有衝突以正本為準。這張卡是寫一批時必須知道的全部，不用再讀完整手冊。

## 收不收
- 全部收（品牌平台、MV、自家作品、敏感／政治題材都收，不換圖）。只有「所有來源都找不到內容」才 `decision: 不收`。
- 重複只收一筆：in 檔 `note_from_selection` 說重複就照它；同一個點子的不同版本（電視版／社群版、專輯裡的歌）也算同一件，回報給主對話決定，不要自己改 decision。

## 先用 in 檔裡已備好的官方資料
- `official.award_line` 就是【得獎】行，**直接用**（獎項、代理商都照官方名單；不要照報導或清單的品牌欄改）。
- `official.awards[].entry_titles` 是官方報名的作品名：寫的必須是這支（同系列別支、別年版本不算）。
- `image_candidates` 裡 `/conversion/` 開頭的就是官方 case board，**優先用**；`/storyboard/` 是影片分鏡格。用之前仍要下載打開看。

## 一句話創意（idea_one_liner）
- 讀者是沒背景的台灣同事；核心點子放最前；**做法要寫到能想像出步驟**（誰做什麼 → 發生什麼），不要壓成名詞。
- 每句有主詞；沒人聽過的品牌寫身分（「祕魯油漆品牌 American Colors」）；人名、事件加身分；雙關、外文標語給原文＋意思；點子靠問題或數字成立時放句首；不用抽象比喻。
- **連續中文（中間沒有標點、引號、英文）≤15 字**；逗號只下在語意斷點，不拆動詞與受詞、形容詞與名詞、主詞與動作。
- 40～55 字為主，**最多 65 字（英文字母、空白也算）**；不寫成效、不寫得獎。

## 讀稿（full_text）
```
<official.award_line>

【背景】…【洞察】…【策略】…（來源沒有就省略）【點子】…【執行】…

資料來源：
<實際打開過的網址，一行一個，2 個以上>
```
- 用自己的話重寫；中位數約 600 字（不含資料來源），篇幅放在點子與執行。不用 `**`。
- **只寫來源裡有的事**：不能用搜尋摘要；看圖只能描述看得到的畫面，不能推測劇情、做法；【洞察】【策略】找不到來源就省略。
- **不寫成效**：活動之後的結果（觀看／收聽／造訪、曝光、分享、市占、增加幾 %、媒體大量報導）、其他獎項（Epica、El Ojo、Eurobest、One Show、D&AD…）、內文重複講「在坎城拿下 X 獅」都不寫；活動之前的背景數字可以。
- 爭議：每件搜「品牌 作品名 controversy／fake／fraud／withdrawn」。**真的有爭議就整件不收**（柏文 2026-11-06）：`decision: 不收`，note 寫爭議內容與來源，讀稿不寫【爭議】段。**算**：有具體來源的造假、灌水、成效不實、抄襲、撤獎指控，把別人的成果說成自己的，得獎後有人公開主張點子是他先提的，法院或主管機關認定說法誤導。**不算、照收、只寫 note**：只有單一整理站或匿名信、對方已否認且無下文、同集團不同分公司的署名歸屬、數字可能高估、版權下架、禁播、一般評論、同品牌別支廣告的爭議。
- 內容重疊只收一筆（柏文 2026-11-06）：同一個點子的不同版本、同一場行動的不同作品、廣播版與影片版，留獎項較多或最有代表性的那筆，其餘 `decision: 重複`＋`same_as`，獎項併進保留那筆；跨批的寫進 note 交給驗收員。
## 標籤（tags）
- 前 8 個固定：`得獎創意案例, 坎城獅子獎, 坎城獅子獎 <年>, 坎城, 坎城創意節, Cannes Lions, 坎城案例, 坎城廣告獎`
- 接著：每座獎的等級與類別（中英）、品牌（中英）、代理商、產業、⭐形式／載體（海報、包裝、裝置、互動網頁…）、⭐製作物（為這個創意另外做出的實體物才算；食物、品牌產品本身、原有媒介上的創意、繪本不算）、手法、媒介、平台、情緒、國家、畫面裡看得到的物件。每個概念加同義詞（中英都常用就都列）。用「, 」串接。Creative Effectiveness 寫「創意實效類」。category 固定「行銷案例」。

## 圖（image_url）
- 順序：`image_candidates` 的 case board → lovethework／ascentialcdn 其他圖 → 官方 YouTube `https://i.ytimg.com/vi/<ID>/maxresdefault.jpg`（不是灰色預設圖；沒有就 hqdefault）→ 報導 og:image。
- **每張下載到 tmp 用 Read 打開看**：是這件作品、看得出點子（字卡、logo、風景不算）；case board 上印成效數字可以用，印得獎字樣的簡報投影照不用。
- curl -I 確認 image/*、<5MB；主機回 octet-stream 或網址有特殊字元打不開，改用 `https://images.weserv.nl/?url=<去掉 https:// 的網址>&w=1600&output=jpg`。不要 http://、redirect、會過期的 CDN（oe=、x-expires、IG／FB／TikTok）。image_shows 寫圖上是什麼。

## 其他欄位
- references 只放實際打開過的網址；awards 照 `official.awards`。
- 查不到文字來源、主要靠推測：`uncertain: true`，note 寫缺什麼。note 提到搜尋摘要時寫清楚「未寫入」。

## 鐵則
- **絕對不能用 rm／unlink／trash 或任何刪檔指令**（暫存、空檔、錯誤頁都一樣），用不到的搬 `tmp_<批號>/old/`。
- 腳本、網頁、圖只放自己的 `tmp_<批號>/`，不用 /tmp、scratchpad，不在 tools/ 或別的資料夾建檔，不改別批的檔，不寫 Google、不上傳、不 git。
- 每寫完 3～4 件先寫一次 out 檔；用 curl 抓網頁、同站間隔 1 秒，不登入、不繞付費牆。
- 寫完：程式檢查（筆數、JSON、格式、字數、連續中文、標籤前 8 個、image/*）＋**人工逐件重讀一句話與讀稿**。
